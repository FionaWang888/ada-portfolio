01 · Problem

解决什么问题

PAIN 01

取数低效

经营数据散落在多个看板、数仓与目标系统，一次完整分析需人工切换拼表 2–4 小时。

PAIN 02

归因靠个人经验

同一个"订单为什么降"，不同分析师结论差异大，质量取决于"是谁写的"而非"方法论是否正确"。

PAIN 03

响应滞后

发现问题 → 找分析师 → 人工排查，链路通常 T+1 起，无法支撑及时经营决策。

02 · Architecture

分层能力设计按「解决什么问题」递进建设

L1 · 去哪看

数据查询层

自然语言查数：意图识别（指标 × 时间 × 区域）→ 自动路由到正确数据源（业务看板 / SQL / 指标平台），模糊问法主动追问而非猜测。

L2 · 为什么（核心亮点）

分析诊断层

异动检测 + 多维归因引擎：排除法 + 连环替代法，每个因素量化贡献度（如「天气贡献 -5.2pp」），输出结构化归因报告。

L3 · 怎么办

决策支持层

月度预测、节假日保障、目标拆解（大区→城市）、周/月复盘报告自动生成，形成分析闭环。

架构模式：复用平台原生的 Skill 发现与匹配机制（非自建 Router），自定义业务 Skill 作为方法论增强层，与取数、文档、可视化等通用 Skill 协同编排。

03 · Knowledge System

知识库与指标图谱怎么搭归因能力的地基

ADA 能"讲道理"的前提，是业务知识被组织成机器可推理的结构。我分三步搭了这套知识体系。

STEP 1 · 指标因果图谱

把散在脑子里的指标关系，变成显式推理规则

先和业务专家把核心经营指标的联动逻辑梳理成一张因果图谱：指标是节点，关系是边，只保留四种类型——分解（数学恒等，如收入 = 可用车数 × 周转 × RPT，资产/订单/用户三种分解视角）、影响（统计相关，如天气分每降 10 分订单降 5–15%）、抑制（trade-off，如提价升 RPT 抑制订单量、加车稀释周转）、传导（因果链，如坏天气 → 用户数降 → 订单降 → 收入降）。图谱里同时编码了 5 条归因推理规则：天气优先排除、供给侧先于需求侧、分解关系用连环替代法量化而影响关系用基准对比估算、禁止把相关性当因果性、各因素贡献度加和须逼近总变化（误差 >5% 即判定分析有错）。

STEP 2 · 协同建设机制

让多位分析师能一起维护，且 AI 永远不写入

图谱不能只活在一张 Excel 里。我用零代码平台搭了协同应用作为唯一数据源：指标字典、因果关系、异动规则、变更历史四张表，按 9 个业务模块（经营产出 / 用户 / 资产 / 调度 / 易得 / 用工 / 易还 / 外部因素 / 过滤指标）划分 Owner，各领域分析师只维护自己模块，跨模块关系归目标模块 Owner，行级权限控制。查询侧用嵌入式图数据库做引擎，每次查询前自动比对版本号增量同步（全量重建约 200 节点 + 500 边，2 秒内）。两条防幻觉硬约束：AI 只做格式校验、环路检测和一致性提示，所有写入必须人类逐条确认；每次变更自动记快照，支持任意版本回滚。

STEP 3 · 策略知识库

从"指标为什么变"走到"该怎么办"

图谱回答归因，策略库回答行动。我把团队分析经验结构化为 8 大类异动要素（外部客观 / G 端治理 / 竞对 / 定价 / 内部产能 / 内部经营策略 / 资产状态 / 系统与工单），配套打分排序机制；再将 30+ 条分析策略编译成"策略原子"——监控范围（城市分层、重要性过滤）、对比基准（双基准、剔除天气、MTD 对齐）、异动判定（双门限、分级阈值、只判恶化）、归因分解（乘法链倒推、互斥完备分解、RPT 桥）、下钻定位与焦点呈现六类，策略之间按「收敛 → 分层 → 基准 → 判定 → 分解 → 下钻 → 收口」串成流水线。知识来源双轨：自上而下的场景 SOP 沉淀，加自下而上的真实案例与周会复盘回流。

STEP 4 · 知识运营与自迭代

让知识库复利增长，而不是一次性工程

知识库方法论上我放弃了纯 RAG（检索无积累，每次从零拼凑），采用「原始资料只读 → LLM 增量编译 Wiki → Schema 约束行为」的三层架构：新资料通过 Ingest 整合进既有页面并维护交叉引用，Query 产出的好分析归档回库，定期 Lint 做矛盾检测、孤立页清理和健康检查——知识编译一次持续复用。Agent 自身同样按此运营：记忆分层（长期记忆容量治理 + 每日记录 + 跨会话检索），并设计了「记忆 → Skill」自迭代闭环——反复验证的经验进候选队列，定时蒸馏成 Skill 草稿，固定样本验证后人工审核、版本化发布。知识库的繁琐在于维护，人负责筛选与判断，LLM 负责其余一切。

这套体系正在向下一代演进：将指标、关系、规则、策略进一步编译入关系型数据库（知识 13 表），由离线编译服务统一生产、治理后台审核发布，支撑 Agent 自主规划分析的通用商分能力。

05 · Quality & Eval

质量与评测体系用户敢用的前提是它不出错

专家基准评测 · 已落地，归因一致率 92%

以历史周会上专家人工识别并归因过的异动案例作为 ground truth 构建评测集：让 Agent 基于案例重跑历史数据、还原当时的异动场景独立完成归因，与专家历史结论逐案比对——归因结论一致率 92%。标尺来自业务专家与历史数据，而非模型自评。

六维评测框架 · 规划中（长期监控）

下一阶段建立常态化质量监控：数据查询准确性 25% · 异动归因质量 25% · 业务知识 15% · 安全合规 15% · 输出规范 10% · 交互体验 10%，每个 case 5 分制、加权 ≥3.5 合格，配套含负样本（如"未达异动阈值不应误判"）的标准测试集，每轮迭代回归评测，长期跟踪六维质量水位。

  • 口径一致性铁律：订单 ↔ 收入 ↔ 客单价互为约束，修正任一变量必须重算整个三角并三方校验
  • 幻觉兜底：生成端与验证端不共用同一假设，结论用独立数据源交叉验证；规律用同年实测验证而非模型假设；图谱写入人类逐条确认
  • 诚实边界：竞对、政策等无法量化的因素如实说明，不强行凑解释；数据不确定时明说"我不确定"
  • 安全红线：不编造数据、不执行写操作、不访问越权数据、拒绝提示词注入
