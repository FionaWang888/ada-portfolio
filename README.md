## 分层能力设计

- **L1 · 去哪看** — 自然语言查数：意图识别（指标 × 时间 × 区域）→ 自动路由到正确数据源，模糊问法主动追问而非猜测
- **L2 · 为什么（核心亮点）** — 异动检测 + 多维归因引擎：排除法 + 连环替代法，每个因素量化贡献度（如「天气贡献 -5.2pp」）
- **L3 · 怎么办** — 月度预测、节假日保障、目标拆解（大区→城市）、周/月复盘报告自动生成

架构模式：复用平台原生 Skill 发现与匹配机制（非自建 Router），自定义业务 Skill 作为方法论增强层，与取数、文档、可视化等通用 Skill 协同编排。

## 知识库与指标图谱怎么搭

归因能力的地基，分四步搭建：

1. **指标因果图谱** —— 指标为节点、四种关系为边（分解 / 影响 / 抑制 / 传导），收入含资产、订单、用户三种分解视角；图谱内编码 5 条归因推理规则（天气优先排除、供给侧先于需求侧、分解用连环替代法 / 影响用基准对比、禁止相关性当因果性、贡献度加和误差 >5% 即判错）
2. **协同建设机制** —— 零代码应用作唯一数据源（指标字典 / 因果关系 / 异动规则 / 变更历史 4 张表），9 个业务模块按 Owner 分权；查询侧用嵌入式图数据库，查询前自动版本同步（约 200 节点 / 500 边，重建 <2s）；AI 只辅助不写入，所有变更人类逐条确认、快照可回滚
3. **策略知识库** —— 8 大类异动要素分类 + 打分排序；30+ 条分析策略编译为六类「策略原子」，按「收敛 → 分层 → 基准 → 判定 → 分解 → 下钻 → 收口」串成流水线；知识来源自上而下 SOP 沉淀 + 自下而上案例回流
4. **知识运营与自迭代** —— 放弃纯 RAG，采用「原始资料只读 → LLM 增量编译 Wiki → Schema 约束行为」三层架构，Ingest / Query / Lint 三种操作让知识库复利增长；Agent 记忆分层运营，并设计「记忆 → Skill」自迭代闭环（候选沉淀 → 定时蒸馏 → 验证审核 → 版本化发布）

## 质量与评测体系

用户敢用的前提是它不出错。

- **六维评测框架**：数据查询准确性 25% · 归因质量 25% · 业务知识 15% · 安全合规 15% · 输出规范 10% · 交互体验 10%
- **专家基准评测 · 归因一致率 92%**：以历史周会上专家人工识别并归因过的异动案例作为 ground truth 构建评测集，让 Agent 基于案例重跑历史数据、还原当时异动场景独立完成归因，按六维评分标准打分并与专家历史结论逐案比对——一致率 92%，标尺来自业务专家与历史数据，而非模型自评
- **幻觉兜底**：生成端与验证端不共用同一假设，结论用独立数据源交叉验证；口径三角（订单 ↔ 收入 ↔ 客单价）互为约束
- **安全红线**：不编造数据、不执行写操作、不访问越权数据、拒绝提示词注入
